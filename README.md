# 树文联动编号（tree-doc-numbering）

![icon](icon.png)

---

## 1 一句话概括

给文档树里的子文档标题、以及文档内的标题块一套联动的编号体系：右键设好范围后，新建、删除、拖动、改名都会自动重排；只改标题，文档 ID、正文块、反链都不动。

## 2 主要功能

| 功能 | 说明 |
|---|---|
| 2.1 树编号自动重排 | 右键把某篇文档或整个笔记本设为范围，新增 / 删除 / 拖动 / 改名约 1.5 秒后自动重排整棵子树，全程不弹窗 |
| 2.2 五级内置体系 | 默认编到 5 级（部 / 篇 / 章 / 节 …），每级的模板与计数方式都能单独改 |
| 2.3 正文标题编号 | 文档内 H1~H5 自动按文档标题的章号 / 节号加前缀，`Ctrl+Alt+1…5` 手动设级并级联重算 |
| 2.4 正文自动重算 | 标题块增删改后停顿 1.5 秒，只重算受影响的那一篇；范围外文档绝不触碰 |
| 2.5 跟随自定义排序 | 每级编号顺序取文档树当前显示顺序，拖动即跟着重排 |
| 2.6 排除 | 可排除单篇（子文档照常）或整支，不编号也不占号；排除时自动剥掉旧前缀 |
| 2.7 换格式自愈 | 换模板 / 减层级会先剥掉旧编号再套新格式，不会叠成双层号 |
| 2.8 两条撤销链 | 「撤销上次编号」回退文档标题，「撤销上次正文编号」回退正文；撤销后自动编号自动暂停 |
| 2.9 只改标题 | 文档 ID、ID 路径、正文块 ID、子/孙文档 ID、反链都不变 |
| 2.10 元数据供其它插件读 | `custom-doc-num` / `custom-doc-num-pad` / `custom-doc-num-meta` 写入文档属性，图表公式交叉引用插件据此算范围层级 |

### 2.11 内置五级体系与计数方式

给「选定范围内」的所有子文档按层级编号。**v0.4.0 内置五级体系**（2026-11-07 用户指定，默认就编到 5 级）：

| 层级 | 模板 | 计数方式 | 例子 |
|---|---|---|---|
| 一级 | `{n}【{title}】` | 全书连续 | `1【绪论】` |
| 二级 | `【{n}】{title}` | 按上一级重排 | `【1】研究背景` |
| 三级 | `第{n}部 {title}` | 按上一级重排 | `第1部 试验设计` |
| 四级 | `第{n}章 {title}` | **按上上级重排** | `第3章 测定方法` |
| 五级 | `第{parentN}.{n}节 {title}` | 按上一级重排 | `第3.1节 取样` |
| 六级及更深 | 原样不动 | — | — |

三种计数方式（每级都能在面板里单独改）：

- **全书连续** `global`：整棵树同一层级接着数，换父不回 1。
- **按上一级重排** `local`：每换一个父文档从 1 重数。
- **按上上级重排** `grandlocal`：换父**继续数**，换祖父才回 1。四级的「章」用它，所以同一个 `【1】` 下面的章跨多个「部」仍是 1、2、3…，换到 `【2】` 才重新从 1 开始 —— 与 v0.2 时代「不同部里的章号要连着」是同一条口径。

`第1.1节` 里前一个数字是**父级章号**（`{parentN}`），后一个是**本节号**（`{n}`，按章重排）。
五级全是内置默认格式，每级都能改成你要的样子（英文、编号放后面、换分隔符都行），见 7.4 自定义编号格式与层级。

> **升级说明**：从 v0.3 升上来时，只有「从没自定义过默认设置」的配置会一次性迁移到这套新默认（只改设置、**不改任何文档标题**）；自己调过格式的保持原样，想换就在面板点「恢复内置默认」。

**v0.5.0 起还能给文档正文里的标题块编号**（H1 `1.1.1` / H2 `1.1.1.1` / H3 `（1）` / H4 `1）` / H5 `①`，前缀自动取文档标题里的节号或章号）：快捷键 Ctrl+Alt+1…5 手动触发；**v0.6.0 起支持自动化**——范围内文档的标题块一有增删改，停顿 1.5 秒自动重算，详见 7.5 正文标题编号。

## 3 它解决了思源的哪些问题

| 思源原生 | 树文联动编号 |
|---|---|
| 3.1 没有「按文档树层级自动编号」，编号得手打 | 右键设一次范围，之后结构变化自动重排 |
| 3.2 文档树自定义排序和标题里的号是两回事，一拖就全乱 | 每级顺序直接取文档树当前顺序，拖动即重排 |
| 3.3 正文里「1.1.1 / （1） / ①」要逐级手打，改一处要顺全文 | 前缀自动取文档标题的章号 / 节号，改标题后联动刷新 |
| 3.4 `Ctrl+Z` 撤不到 API 写入的改名 | 插件自带撤销，逐篇还原旧标题 |
| 3.5 手改标题容易误用 `updateBlock` 把正文删光 | 只走 `renameDocByID`，ID 与正文都不动 |
| 3.6 新建 / 删除瞬间 SQL 索引滞后 0.6~2 秒，容易读到旧结构 | 采集层用文件树递归，不靠 SQL 前缀捞子树 |

## 4 和别的实现方式比

以下只比较做法，**未逐一实测第三方插件**【待确认：其它编号类插件的当前功能以各自文档为准】。

| 对比项 | 手写编号 | 思源原生 | 树文联动编号 |
|---|---|---|---|
| 4.1 谁维护编号 | 人 | 无此功能 | 插件按文档树自动重排 |
| 4.2 拖动文档后 | 全文手改 | — | 约 1.5 秒后自动重排 |
| 4.3 正文标题前缀 | 手打 | 无 | 自动取文档标题的章 / 节号 |
| 4.4 计数方式 | 自己定 | — | 全书连续 / 按上级重排 / 按上上级重排，逐级可选 |
| 4.5 撤销 | 靠 `Ctrl+Z` 逐次 | `Ctrl+Z` 撤不到 API 写入 | 插件自带两条撤销链 |
| 4.6 改动范围 | 可能误改正文 | — | 只改标题，ID / 正文 / 反链不动 |

取舍一句话：**书稿层级深、经常拖动或换格式**，用本插件最省事；只是偶尔给两三个文档加个号，手写反而更快。

## 7 用法与详细操作步骤

### 7.1 自动编号（v0.2.0 主要用法）

1. 在左侧文档树里**右键那篇「父文档」**（编号只作用于它下面）；也可以**右键一个笔记本**（整个笔记本的所有文档都编号，笔记本根级文档算一级「部」）。
2. 点 **「设为自动编号范围（新增/删除/拖动自动重排）」**。设定完会立刻先编一次。
3. 之后在范围内发生 **新建文档、删除文档、拖动文档位置、改文档标题**，约 1.5 秒后自动重排整棵子树编号，全程不弹窗。
4. 不想要了：同一个文档/笔记本上右键 →「取消该范围的自动编号」。
5. 只想手动编一次：右键文档 →**「按设定格式给子文档编号」**；右键笔记本 → **「按设定格式给整个笔记本编号」**。

可以同时设多个范围。点右上角 **≡ 列表图标**（`子文档自动编号`）打开面板：总开关、范围清单与移除、「立即全部重排」、「撤销上次编号」。

### 7.2 手动编号（v0.1.0 用法，仍保留）

右键文档 →「按设定格式给子文档编号」。右键任意文档 →「撤销上次子文档编号」。

> **撤销后自动编号会自动暂停**，否则撤销自己发出的改名事件会在 1.5 秒后把编号原样写回去。想继续自动，到顶栏面板把开关重新勾上。

### 7.3 排除部分文档不编号

在文档树里**右键某篇文档**：

| 菜单项 | 效果 |
|---|---|
| 「排除此文档（自身不编号，子文档照常）」 | 这篇文档不编号、不占号，**它的子文档照常编号**（层级不塌） |
| 「排除此文档及子文档（整支不编号）」 | 这一整支都不编号、不占号 |
| 「取消排除（恢复参与编号）」 | 恢复编号，不会叠加前缀 |

排除时插件会**把该范围内已有的编号前缀剥掉**，恢复原标题，避免留下「第02章 附录」和补位后的「第02章 某章」撞号。顶栏面板里能看到排除清单并可移除。

> 实测坑：思源文档树的笔记本节点 `data-node-id` 是**空字符串**，笔记本 ID 在父级 `<ul data-url>` 上。v0.2.0 初版按 `data-node-id` 取 ID，右键笔记本时菜单根本不出现；现改为按 `data-type` 判节点类型、从父 `ul[data-url]` 取 ID。

### 7.4 自定义编号格式与层级（v0.3.0）

点右上角 **≡ 列表图标**打开面板。面板按思源原生对话框布局：**顶部状态卡**（总开关，暂停时整块褪色）、**中部滚动设置区**（格式表格 / 实时预览 / 范围与排除清单）、**底部固定操作条**。控件全用思源原生的 `b3-button` / `b3-select` / `b3-text-field` / `b3-switch`，配色一律取 `--b3-theme-*` 变量，亮色 / 暗色主题自动跟随；没有 emoji、没有写死的颜色。

面板里「编号格式与层级」区：

1. 「作用于」下拉选 **默认设置**（新范围 / 手动编号用）或**某个具体范围**。格式、层级数、计数方式**每个范围各存一套**，互不干扰。
2. 「编号到第 `−` `5` `+` 级」：点 `−` / `+` 在 **1~5 级**间增减；多一级多一行，少一级少一行（v0.4 默认 5 级）。
3. 每一行：左边填**格式模板**，右边下拉选**计数方式**：
   - `全书连续` —— 整棵树同一层级接着数（默认一级）
   - `按上级重排` —— 每换一个父文档从 1 重数（默认二、三、五级）
   - `按上上级重排` —— 换父继续数、换祖父才回 1（默认四级「章」）
   - 每行最右边的 **×（删除号，v0.4.1 新增）**：删掉该级，后面各级的模板 / 计数方式依次上移补位，层级数减 1；删最后一级等价于点 `−`（模板保留，点 `+` 可加回）。只剩 1 级时按钮置灰。改完仍要点「保存并应用」才写入并重排。
4. 下方实时预览当前填写的效果。点 **「保存并应用」** 立刻按新设置重排；点 **「恢复内置默认」** 把模板、计数方式、层级数一起改回 v0.4 五级体系。

| 占位符 | 含义 | 序号 3、父级号 1 时 |
|---|---|---|
| `{nn}` | 补零到两位 | `03` |
| `{n}` | 不补零 | `3` |
| `{parentN}` | **上一级文档的编号** | `1` |
| `{parentNN}` | 上一级编号，补零到两位 | `01` |
| `{title}` | 原标题 | `绪论` |

可直接粘贴的例子（五级各填一行）：

```
v0.4 内置： {n}【{title}】   【{n}】{title}   第{n}部 {title}   第{n}章 {title}   第{parentN}.{n}节 {title}
v0.3 旧式： 第{nn}部 {title}  第{nn}章 {title} 第{nn}节 {title}  第{nn}条 {title}  第{nn}款 {title}
英文：      Chapter {nn} - {title}   Sec {n}: {title}  {nn}. {title}  §{n} {title}  {parentN}.{n} {title}
编号放后面：{title}（第{nn}部）  {title}【{n}】  …
```

- **换格式 / 减少层级都会自动剥掉旧编号再套新格式**，不会叠成 `1【第01部 绪论】`；超出的层级恢复原标题。
- **已知代价**：新内置模板用不补零的 `{n}`，手写的「第1章」与插件生成的「第1章」长得一样，会被当成插件前缀剥掉；中文数字「第一章」、带小数的「第1.1 结果」不受影响。想保留手写编号，把该级模板改成补零的 `{nn}` 即可。
- 成对剥离：`{n}【{title}】` 这类「前缀 + 后缀」模板，只有前缀命中时才剥后缀，所以手写标题末尾的「】」不会被吃掉。
- 忘了写 `{title}`，插件自动补在末尾；模板留空则回退内置默认 —— 不会生成「只有编号、丢了标题」的文档名。
- **「无标题 / 无命名文档 / 未命名文档 / Untitled」等占位标题跳过不占号**，改好名字后自动补号；已挂过旧号的占位文档会先把旧号剥掉。面板上有开关可关掉。
- 规则细节见 `格式模板约定.md`。

### 7.5 正文标题编号（v0.5.0）

给**文档正文里的标题块**（H1~H5）加编号，编号前缀自动取**文档标题里的节号或章号**：

| 层级 | 默认模板 | 编号逻辑 | 例子（文档《第1.1节 取样》） |
|---|---|---|---|
| H1 | `{prefix}.{n}` | 前缀 = 节号（或章号）+ 本层序号 | `# 1.1.1 样品制备` |
| H2 | `{h1}.{n}` | 接所属 H1 号再加一段 | `## 1.1.1.1 清洗` |
| H3 | `（{n}）` | 按所属 H2 重排 | `### （1）先用清水` |
| H4 | `{n}）` | 按所属 H3 重排 | `#### 1）水温控制` |
| H5 | `{cn}` | 按所属 H4 重排 | `##### ①细节` |
| H6+ | 不编号 | — | — |

- **快捷键 Ctrl+Alt+1…5**：把光标所在段落设为第 N 级标题并编号，同时**级联重算该文档全部标题编号**（只写编号确实变化的块，幂等）。
- 文档标题只有章号时用章号兜底：《第3章》的 H1 编成 `3.1`、H2 编成 `3.1.1`。
- **前缀三种写法都认**（v0.6.3）：`第2.1节 …`、`第3章 …`、以及 **`2.1 …`** 这种纯数字开头（树编号第 2 级模板 `{parentN}.{n} {title}` 产出的就是这个形态，不认它会自相矛盾）。纯数字形态必须带小数点且后面有空格或顿号/冒号分隔，所以「2024 年度总结」「3 个方法」不会被误判。
- **没有节号也没有章号的文档自动跳过**，不瞎编前缀。
- 模板每级可自定义（面板「正文标题编号」区），占位符：`{prefix}` 节/章号、`{n}` 本层序号、`{h1}` 所属一级编号、`{cn}` ①②…、`{title}` 原标题。模板含 `{title}` 时标题位置由模板控制；不含则编号自动接在标题前，数字收尾补一个空格。
- **「撤销上次正文编号」**在面板底部操作条和正文区都有入口，逐块还原最近一轮改动；撤销成功后**正文自动重算会暂停**（要继续去面板重新开启）。

> **安全闸（2026-11-07 真机事故教训）**：读不到段落文字绝不编号、剥完只剩井号的块绝不写、光标在文档根上拒绝执行、撤销跳过原文为空的记录。正文改写全部走 `updateBlock` 逐块提交，中断即停，不做半套编号之后的继续写。

### 7.6 正文自动编号（v0.6.0）

面板「正文标题编号」区新增开关 **「标题变化后自动重算」**（默认关，自己开启）：

- **作用范围复用「自动编号范围」**：文档范围 = 该文档**及其全部子文档**（与树编号同口径）；范围外文档的正文绝不触碰。
- **触发**：思源保存正文时推 `savedoc` 事件（自带文档 ID），插件只筛「标题块操作 / 删除」进入队列，普通段落改动直接忽略；**停顿 1.5 秒**后只重算受影响的那一篇（打字过程中编号不跳动）。
- **树编号联动**：文档被树编号改名（节号/章号变了）→ 该文档正文前缀自动跟着刷新一轮；树编号撤销还原标题后同样联动。
- **防自激**：整篇重算幂等，只写编号变化块；插件自己写入引发的事件下一轮 plan 为空、自动收敛。另有**熔断**：同一批改动连续重复 3 轮（编号被别的东西反复改回）→ 停掉该文档的自动编号并弹提示，到面板关掉再开启即复位。
- 快捷键 Ctrl+Alt+1…5 保留不变；自动化补的是「用思源自己的方式改标题后不用手按」。

### 7.7 立即编一遍 + 深度归一（v0.6.1）

自动化只在**文档被保存**时才跑，所以**刚装上插件时，范围里那些很久没编辑过的文档一次编号都没有**——不是算错，是从来没触发。v0.6.1 补了两件事：

- **面板「现在编」**（正文标题编号区）：把「自动编号范围」里所有文档的正文标题按当前模板编一遍。第一次点只**预检报数**（几篇、几处），按钮变成「确认写入 N 处」，再点一次才写库；整批共用一份撤销快照，点「撤销上次正文编号」一次全还原。只改编号、不动标题级别，普通段落与列表不碰。
- **「立即全部重排」现在管两件事**（v0.6.2）：先按文档树给范围内文档标题编号，再顺带把每篇的正文标题编一遍，一次点击两套都齐。正文功能关掉（面板「启用快捷键」关）时只重排文档标题。撤销仍是两条独立链：面板左下「撤销上次编号」回退文档标题，正文区「撤销上次正文编号」回退正文。
- **文档内深度归一**：篇内**没有 H1** 时（节级文档常见：标题直接从 H2 起），把最浅那一级当「一级」套模板。于是《第5.1节》的顶标题是 `5.1.1`（不是字面级别的 `5.1.1.1`），下一层才是 `5.1.1.1`。**有 H1 的文档 shift=0，输出与 v0.6.0 逐字一致**。井号个数永远按原级别不变，只是「用第几级模板」变了。

| 文档内标题 | 归一前（字面级别） | 归一后 |
|---|---|---|
| `## 加载环境与数据准备` | `## 5.1.1.1 加载环境与数据准备` | `## 5.1.1 加载环境与数据准备` |
| `### 安装包检测并自动安装` | `### （1）安装包检测并自动安装` | `### 5.1.1.1 安装包检测并自动安装` |
| `#### 联网检查` | `#### 1）联网检查` | `#### （1）联网检查` |

### 7.8 多级自定义排序（重要）

**每一级**的编号顺序严格取文档树当前显示的顺序（`listDocsByPath` 的 `files` 数组），不按标题文字、不按创建时间、不按 `sort` 数值排序。拖动任何一级的子文档，该级以及受影响的章/节号都会跟着重排。

要让顺序完全听你拖的，**请在文档树里把该层的排序方式切成「自定义排序」**；如果某层设的是「按名称升序/降序」，编号就跟随那个排序结果，不会按你拖的位置来。本插件不擅自改笔记本的排序设置。

拖动时思源会广播 `filetreeSortChanged`，事件自带新的 `childIDs` 顺序；插件在内核缓存刷新前就先用这份顺序编号，避免编号慢半拍。

### 7.9 编号规则细节

- **内置默认**是五级新体系（见 2.11），数字不补零、`{parentN}` 取父级章号。每级模板都可在面板里改（见 7.4）。
- 每次执行先剥掉插件自己加的编号再重排，保证幂等，也保证文档被挪到别的层级时前缀会跟着换。
- 剥离按「当前格式 + 上次格式 + 上次全局默认 + 全局默认 + 核心内置旧版兜底 + 旧版硬编码」逐个生成正则。`{nn}` / `{parentNN}` 生成 `\d{2,}`，`{n}` / `{parentN}` 生成 `\d+`；中文数字、带小数的手写编号仍安全。
- 前缀 + 后缀式模板（如 `{n}【{title}】`）按**成对规则**剥：只有前缀命中才剥后缀，避免误伤手写标题末尾的 `】`。
- **层级数默认 5、可增减到 1~5**；每级可选「全书连续」/「按上级重排」/「按上上级重排」。超出层级数的文档剥掉编号、恢复原标题。
- `grandlocal` 的分组键是「层级 + 祖父节点 ID」，所以章号跨父（部）连号、换祖父（`【n】`）才回 1；若上级本身被排除或跳过、没有编号，其下级的 `{parentN}` 退化为 `0`（边界情况，如实标注）。
- **刚新建、还没起名的文档**（`无标题` / `无命名文档` / `未命名文档` / `Untitled` / `新建文档`，含带序号变体）不编号、也不占号，免得写出「第03章 无标题」或在用户输标题时抢着改；用户改好名字后自动补号。顶栏面板可关掉这条。
- Syncthing 生成的 `(Conflicted …)` 副本不参与编号、不占号。
- 只改范围内子文档的标题，**不改父文档自己的标题**、不改正文、不换文档 ID。
- **v0.4.1 重叠范围归属**：同时把「某文档」和「包含它的整个笔记本」设为范围时，外层范围只编号到该文档节点本身、不再下钻它的子文档，子文档归更具体的文档范围管。否则同一篇文档会按两套层级口径轮流改写（真机表现：文档树标题不停闪烁）。自动检查另有熔断：同一批改名连续重复 3 轮就暂停自动编号并提示检查范围设置。

### 7.10 只改标题，别的都不动

实测（思源 3.8.9）：改标题走 `/api/filetree/renameDocByID`，**文档 ID 不变、ID 路径不变、正文块 ID 不变、子/孙文档 ID 不变**；只有文档标题和人类可读路径 `hpath` 更新。所以正文、块引用、反链都不受影响。

> 反面教材：用 `updateBlock` 去改文档块会把整篇正文删光（本项目 2026-10-28 实际事故），本插件绝不调用它。

### 7.11 撤销

思源的 Ctrl+Z **撤不到 API 写入**（撤销栈只记编辑器自己发起的操作）。插件改名前把「每篇的旧标题」存进自己的数据文件，右键「撤销上次子文档编号」逐篇改回；撤销成功后清空记录并**暂停自动编号**（见 7.2）。

## 8 现有不足

- 默认编到 **5 级**，可在面板里增减到 **1~5 级**；**六级及更深始终不编号**（`MAX_LEVEL = 5` 写死）。默认 5 级意味着升级后第四、五层也会被编号 —— 不喜欢就把层级数调回 3。
- 只处理「范围根以下」，不会改范围根自己的标题；**笔记本范围**下每篇根文档算一级「部」，笔记本名字本身不改。
- 单棵树最多展开 2000 个节点、8 层，超出会截断【待确认：极大书稿未实测】。
- 自动触发靠思源 `ws-main` 事件；若某版本事件名变化，会退化成「手动右键才更新」，不会误改数据。
- 模板若写成 `{n}. {title}`，标题里手写的「1. 绪论」会被当成插件旧前缀剥掉 —— 这是自定义该格式的必然结果（见 `格式模板约定.md` §3）。**v0.4 内置 `第{n}章` 也是单数字**，手写「第1章」会被剥掉；中文数字「第一章」不受影响。
- 真人鼠标点顶栏面板改格式、真人拖动文档树、真人右键点击仍未直接实测【待确认】，验的是同一份接口 + 面板 DOM + 与 UI 同格式的事件 payload。
- 手机端、单位机、笔记本、其他思源版本未测；只在**家机 DESKTOP-PLK096N / 思源 3.8.9** 桌面端实测【待确认】。
- **正文自动编号的撤销只有「最近一轮」**：自动重算轮数多，`body-undo-last.json` 每轮覆盖，只能撤销最后一轮，再往前的轮次没有逐轮栈。
- 手动改文档标题（不经树编号改名）不会立刻触发该文档的正文重算，下次正文变化或树编号联动时补上。
- 自动化开启时若在标题里**打字打到一半**停顿超 1.5 秒，那一轮可能给「半截标题」挂上编号；继续打字后下一轮自动收敛成正确形态（编号位置不吞标题）。
- 其它 E2E 脚本运行期间若 `bodyAuto` 开着，树编号联动会给测试树文档的正文也编一轮号（实测发生过，不影响各脚本断言，但快照会被占用）。
- 新建文档头几秒 SQL 未就绪时，若立刻建标题，正文自动编号第一轮可能跳过，下一次事件补上（宁跳过、不误写）。

## 9 技术实现（附录）

- **采集层是纯文件树递归**：从范围根（文档或笔记本根 `/`）一层层调 `listDocsByPath`，用返回项的 `subFileCount` 判断要不要往下展开、`name` 拿实时标题、`files` 数组拿该级自定义排序。不再用 SQL 按 `path` 前缀捞子树 —— 新建/删除瞬间 SQL 索引有 0.6~2 秒滞后，会读到旧结构。
- 叶子文档（`subFileCount = 0`）不调 `listDocsByPath`，内核对它报错。
- 自动触发监听 `ws-main` 的 `create` / `removeDoc` / `rename` / `filetreeSortChanged`；打字产生的 `savedoc`、`transactions`、`databaseIndexCommit`、`syncPending` 一律忽略。实测每个事件会广播**两次**，故一律防抖 1.5 秒。
- **结构指纹**（层级 + ID + 实时标题 + 各级顺序）比对：树没变就不写；插件自己改名引发的 `rename` 最多让检查空转一轮（`buildPlan` 幂等、plan 为空不落库），随后指纹收敛，不会自激。
- **v0.4.1 重叠范围剪枝**：`collect(target, {pruneIds})` 让外层范围不下钻已被更具体文档范围接管的子树（节点自身保留）；自动检查另有振荡熔断，同一组 `from→to` 连续 3 轮就暂停自动编号并提示。只读探针 `python probe/probe_v041.py`（7 项）。
- 写完回读文件树校验标题（接口返回成功 ≠ 结果正确）。
- **笔记本范围**用一个虚拟根 `path="/.sy"`，`listDocsByPath(notebook, "/")` 返回根级文档当作一级「部」，其余递归逻辑与文档范围完全相同。
- `index.js` 由 `build.py` 把 `src/numbering.js`（纯函数）+ `src/plugin.js`（插件主体）拼成；改源码后跑 `python build.py`，别手改 `index.js`。单测：`node test/numbering_unit.js`（70 项，A–F 六系列）。
- 真机验证：`python test/e2e_defaults.py`（v0.4 五级新体系，30 项）、`python test/e2e_live.py`（基线 42 项）、`python test/e2e_auto.py`（自动触发 + 排除，47 项）、`python test/e2e_notebook.py`（整个笔记本，23 项）、`python test/e2e_formats.py`（格式 / 层级 / 占位 / 面板，66 项，报告 `验证报告-格式自定义.md`）。五者都会备份并恢复你已有的自动编号配置；`e2e_formats.py` / `e2e_auto.py` / `e2e_live.py` 还带退出兜底，异常也写回配置。
- 四套旧链路回归通过 `test/live_lib.py` 的 `LEGACY_DEFAULTS` **显式锁定 v0.3 旧口径**（`第01部` / 3 级 / 两种计数），否则 v0.4 新默认会让写死的断言全崩。`e2e_live.py` 跑前先 `python probe/probe_rename.py --fresh` 重建测试树。
- **面板样式**写在 `src/plugin.js` 的 `PANEL_CSS` 常量里（`<style id="dn-panel-style">` 随面板注入），类名统一 `dn-` 前缀，不污染宿主界面。图标是内联线性 SVG，颜色走 `currentColor`。真机核对：`python probe/probe_theme.py`（主题变量）、`python probe/probe_panel.py`（DOM / 配色 / 结构）、`probe/shot_panel.py`（亮 / 暗主题截图，需带 Pillow 的解释器）。
- **正文编号核心**是 `src/body_numbering.js` 纯函数（`buildBodyPlan`：取前缀 → 按层级生成编号 → 剥旧号 → 只输出变化块），由 `build.py` 与文档树核心一起拼进 `index.js`。块采集走 `getChildBlocks`（实时、顺序可信）+ `getBlockKramdown`（实时逐块原文），**SQL 只作元数据兜底**——新建/删除瞬间 SQL 索引滞后 0.6~2 秒，拿它当数据源就会读到空标题（v0.5.0 首版真机事故根因）。新块 SQL 未就绪、层级读成 0 时，从实时 kramdown 的 `#` 个数兜底推导。
- **正文自动编号只认 `savedoc`**（探针 `probe/probe_body_auto.py` 实测）：`detail.data.rootID` 是文档 ID、`detail.data.sources[].doOperations` 里 `op.data` 是 DOM 片段，`data-type="NodeHeading"` 直接可判标题操作；`transactions` 事件里 update/delete 的 `op.rootID` 实测为空串、定位不了文档，弃用。删除 op 的 data 为空、分不清删的是不是标题 → 对该文档整篇复核一轮（幂等）。
- **范围判定** `docInTargets`：文档范围认「该文档 + 其全部子文档」——子文档 `path` 形如 `/<父ID>/<子ID>.sy`（父目录段**不带** `.sy`，父自己的 path 才带），前缀必须用去掉 `.sy` 的父 ID 段比；笔记本范围比 box。树改名联动直传**新标题**进队列，避免 SQL 索引滞后读到旧名误判「无前缀」。
- 正文离线单测：`node test/body_numbering_unit.js`（24 项，G 系列）；真机：`python test/e2e_body_numbering.py`（快捷键路径 18 项）、`python test/e2e_body_auto.py`（自动化全链路 17 项，报告 `验证报告-正文自动编号.md`）。
